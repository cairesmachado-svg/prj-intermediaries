Entrega-01 — Coding regulatory intermediaries in EU green-transition
legislation. Prepared by Igor Caires Machado for Prof. David Levi-Faur.

**v2 (05/09/2026), current.** Revised after a critical review of v1
identified that the original PoC built a mechanism-screening system, not
intermediary coding. See `Anexos/RIT_CODING.md` and
`Anexos/GOLD_STANDARD_VALIDATION.md` for what changed. v1 (Portuguese,
screening-only) is kept in `v1_retirado_05-09_pre-revisao/` for the record —
do not send it.

## Contents

- **`Research_Note_Intermediary_Coding_EN.docx`** (and `.md`) — the main
  document, in English: theoretical understanding, the two-stage design
  (Stage A screening / Stage B R-I-T coding), validation results, and a
  one-paragraph methodological note on prior ARENAS experience. Read this
  first.

- **`Anexos/`** — supporting evidence:
  - `README.md` — what was run and the Stage A screening results (4 acts,
    1,079 lines).
  - `METODOLOGIA.md` — why each methodological choice was made this way,
    including the Stage A/Stage B correction (section 11).
  - `CODEBOOK.md` — Stage A strings/rules, with an actor/mechanism/instrument
    tag per pattern.
  - `RIT_CODING.md` — Stage B: the four R-I-T coded provisions, including the
    conditional Climate Benchmarks case.
  - `GOLD_STANDARD_VALIDATION.md` — precision/recall/F1 of Stage A against a
    manual, regex-free reading.
  - `scripts/` — reproducible source (`collect.py`, `codebook_screen.py`,
    `combine.py`).
  - `data/` — raw EUR-Lex HTML per act, Stage A datasets (`*_dataset.csv`,
    `combined_dataset.csv`), and the Stage B table
    (`rit_coded_sample.csv`).

## How to reproduce (Stage A)
```
cd Anexos/scripts
python collect.py <CELEX> <slug>
python codebook_screen.py <slug> <CELEX>
python combine.py csrd ecolabel climate_benchmarks ets_verification
```
Requires Python with `requests` and `beautifulsoup4`. Stage B
(`rit_coded_sample.csv`) is manual coding, not generated by a script.
